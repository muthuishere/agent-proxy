# Spec: One-Line Install via GoReleaser

**Status:** Proposed
**Priority:** High
**Depends on:** `install.sh`, `install.bat`, `cmd/agentproxy/casetup.go`, `bin/claudeproxy`, `bin/codexproxy`, `bin/copilotproxy`, `bin/agentproxy-start`, existing `Taskfile.yml`

---

## Problem

Today AgentProxy can only be installed by cloning the repo and running `./install.sh`, which assumes Go 1.23+ is on the user's machine and effectively builds from source. There is no path for a non-developer (or a developer who simply wants the tool, not the source) to install AgentProxy with a single command — comparable to `npm install -g <pkg>`, `brew install <pkg>`, or `curl … | sh`.

We need a published-binary distribution flow so users can:

1. Run one command (with `sudo` only where required for OS trust store changes).
2. Get the `agentproxy` binary plus the `claudeproxy` / `codexproxy` / `copilotproxy` / `agentproxy-start` wrappers on `PATH`.
3. Get the local MITM CA generated and trusted in their OS trust store.
4. Be ready to run `agentproxy-start` and then a wrapper (`claudeproxy`, etc.) immediately.

GoReleaser is the intended build/publish tool because the project is already Go-only (`go.mod`, `cmd/agentproxy`, vendored `third_party/goproxywss`).

---

## Goals

- Publish prebuilt, versioned AgentProxy binaries for macOS (amd64 + arm64), Linux (amd64 + arm64), and Windows (amd64) on every tagged release.
- Provide a single-command install for each major platform that does not require Go to be installed on the user's machine.
- Reuse the existing `agentproxy ca-setup` flow for CA generation and trust — no new cert pipeline.
- Keep `sudo` usage explicit and minimal: only for (a) writing into a system-wide install dir if chosen, and (b) trusting the CA in the OS root store.
- Ship the wrapper scripts (`claudeproxy`, `codexproxy`, `copilotproxy`, `agentproxy-start`) inside the release artifact, not regenerated by the installer.
- Provide a clean uninstall that removes the binary, wrappers, and trusted CA.

---

## Non-Goals

- Replacing the developer flow (`task prepare-local`, `task dev`, building from source). Those stay as-is for contributors.
- Code-signing / notarizing macOS or Windows binaries in the first iteration. (Tracked separately; users may see Gatekeeper / SmartScreen warnings on first run until then.)
- Auto-update of the installed binary.
- Distributing via the official Homebrew core tap or winget store. A self-hosted Homebrew tap and a Scoop bucket are in scope; submission to upstream registries is not.
- A GUI installer (.pkg / .msi). Shell-script + package-manager flows only for v1.
- Bundling Node, Python, or any agent runtime — users still install `claude`, `codex`, `gh copilot` themselves.

---

## Functional Requirements

### REL-1 — GoReleaser configuration

Add `.goreleaser.yaml` at the repo root that:

- Builds `cmd/agentproxy` for: `darwin/amd64`, `darwin/arm64`, `linux/amd64`, `linux/arm64`, `windows/amd64`.
- Embeds version, commit, and build date via `-ldflags` into `cmd/agentproxy/version.go` (or equivalent), surfaced by `agentproxy version`.
- Produces archive artifacts named `agentproxy_<version>_<os>_<arch>.tar.gz` (zip on Windows) containing:
  - `agentproxy` (or `agentproxy.exe`)
  - `bin/claudeproxy`, `bin/codexproxy`, `bin/copilotproxy`, `bin/agentproxy-start` (the existing scripts, unchanged shell logic)
  - `config/agentproxy.yaml`, `config/patterns.yaml`, `config/pii_patterns.yaml` as default configs
  - `install.sh` / `install.bat` (the new short post-extract installer — see REL-2)
  - `LICENSE`, `THIRD_PARTY_NOTICES.md`, `README.md`
- Generates a `checksums.txt` (SHA256) for all archives.
- Publishes to GitHub Releases on tag push (CI workflow under `.github/workflows/release.yml`).

### REL-2 — Curl-pipe installer

Add `scripts/install-online.sh` (and `scripts/install-online.ps1` for Windows) hosted in the repo and pointed at by a stable URL (e.g. `https://raw.githubusercontent.com/muthuishere/agent-proxy/main/scripts/install-online.sh`).

The shell installer must:

1. Detect OS and arch; pick the matching release archive.
2. Resolve the requested version (default: latest GitHub release; overridable via `AGENTPROXY_VERSION=vX.Y.Z`).
3. Download archive + `checksums.txt`; verify SHA256.
4. Extract into a staging dir.
5. Install binary + wrappers into:
   - **User mode (default):** `$HOME/.local/bin` (no sudo needed, but warn if not in `PATH`).
   - **System mode (`--system` or detected `EUID=0`):** `/usr/local/bin` (requires `sudo`).
6. Run `agentproxy ca-setup` to export the CA cert to `$HOME/.agentproxy/certs/`.
7. Trust the CA in the OS root store using `scripts/trust-ca.sh` semantics (already exists in repo). This step prompts for `sudo` on macOS/Linux. If the installer is non-interactive, it skips trust and prints the exact `sudo` command to run.
8. Print a 3-line "next steps" block: start proxy, run agent wrapper, where to find logs.

User-facing one-liner shape:

```bash
curl -fsSL https://raw.githubusercontent.com/muthuishere/agent-proxy/main/scripts/install-online.sh | bash
```

Windows equivalent (PowerShell):

```powershell
iwr -useb https://raw.githubusercontent.com/muthuishere/agent-proxy/main/scripts/install-online.ps1 | iex
```

### REL-3 — Homebrew tap (macOS / Linux)

- Configure GoReleaser's `brews:` block to publish a formula to a self-hosted tap repo (`muthuishere/homebrew-agent-proxy`) on each release.
- Formula installs the binary + wrappers into the Cellar, symlinks into `/usr/local/bin` (or `/opt/homebrew/bin` on Apple Silicon).
- Formula runs `agentproxy ca-setup` post-install to export the cert, but **does not** auto-trust — prints the exact trust command the user must run with `sudo`. Rationale: brew formulae shouldn't silently mutate system trust stores.

User flow:

```bash
brew tap muthuishere/agent-proxy
brew install agentproxy
sudo agentproxy ca-setup --trust   # explicit trust step
```

### REL-4 — Scoop bucket (Windows)

- Configure GoReleaser's `scoops:` block to publish a manifest to `muthuishere/scoop-agent-proxy`.
- Post-install hook prints the `certutil -addstore "Root" <cert>` command for the user to run from an elevated shell.

User flow:

```powershell
scoop bucket add agent-proxy https://github.com/muthuishere/scoop-agent-proxy
scoop install agentproxy
```

### REL-5 — `agentproxy ca-setup --trust` flag

Extend the existing `cmd/agentproxy/casetup.go` so that `agentproxy ca-setup --trust` performs both export and OS trust (today the trust step lives in `scripts/trust-ca.sh` and is wired only via Taskfile). This makes the install flow self-contained — package-manager users don't have to chase a separate shell script.

Behavior:

- `agentproxy ca-setup` (existing) — export only, print manual trust instructions.
- `agentproxy ca-setup --trust` (new) — export + invoke OS trust commands. Requires elevation; if not elevated, re-execs itself under `sudo` (Unix) or shows UAC prompt (Windows).
- `agentproxy ca-setup --untrust` (new) — remove cert from OS trust store. Used by uninstall.

### REL-6 — Uninstall parity

Update `uninstall.sh` / `uninstall.bat` (and Homebrew/Scoop manifests) to:

1. Run `agentproxy ca-setup --untrust` before removing the binary.
2. Remove `~/.agentproxy/` (cert + runtime dirs) only if the user passes `--purge`.
3. Remove the binary and wrapper symlinks from the install dir.

### REL-7 — Versioning + release workflow

- Tags follow `vMAJOR.MINOR.PATCH` (semver).
- A GitHub Actions workflow on tag push runs `goreleaser release --clean`.
- Release notes are auto-generated from commits since previous tag plus a hand-written highlights section pulled from `CHANGELOG.md`.

## Acceptance Criteria

- [ ] `goreleaser release --snapshot --clean` produces archives for all five target platforms with binary, wrappers, and default configs inside.
- [ ] On a clean macOS arm64 machine **without Go installed**, the curl-pipe installer succeeds end-to-end and `agentproxy version` prints the released version.
- [ ] On a clean Ubuntu 22.04 machine without Go, same as above.
- [ ] On a clean Windows 11 machine, the PowerShell one-liner installs binary + wrappers and runs `agentproxy ca-setup --trust` with a UAC prompt.
- [ ] After install, running `agentproxy-start` then `claudeproxy --version` (or any claude invocation) succeeds with masked traffic visible in `~/.agentproxy/logs/traffic.jsonl` (or the configured log path).
- [ ] `brew install muthuishere/agent-proxy/agentproxy` installs the binary + wrappers; post-install message tells the user how to trust the CA.
- [ ] `scoop install agentproxy` does the same on Windows.
- [ ] Running `uninstall.sh` removes binary, wrappers, and the OS-trusted CA. `~/.agentproxy/` is preserved unless `--purge` is passed.
- [ ] A tagged push to `main` (e.g. `git tag v0.1.0 && git push --tags`) triggers GitHub Actions, builds artifacts, publishes the release, and updates the brew tap and scoop bucket.

## Implementation Notes

- The existing `install.sh` becomes a *post-extract* installer used inside the release archive — it should no longer call `go build`. Keep the developer-source flow under a different name (e.g. `scripts/install-from-source.sh`) or as a Taskfile target only.
- `bin/claudeproxy` etc. already read `$HOME/.agentproxy/certs/agentproxy-ca-cert.pem` — keep that path stable; the GoReleaser flow must put the cert there to avoid touching the wrapper logic.
- `scripts/trust-ca.sh` is the canonical trust logic; `agentproxy ca-setup --trust` should shell out to platform commands directly (so the binary is self-sufficient) but the shell script can stay for Taskfile-based dev flow.
- For the curl-pipe installer, follow the standard pattern used by `rustup`, `volta`, `mise` — single shell file, idempotent, refuses to run as root by default for user-mode install, opt-in `--system`.
- Embedding default configs: ship them in the archive but install them only if the target path is empty, never overwrite a user's existing `~/.agentproxy/agentproxy.yaml`.
- Code signing on macOS/Windows is deferred; document the Gatekeeper / SmartScreen workaround in README until signing is in place.

## Verification

- `goreleaser check` passes in CI.
- `goreleaser release --snapshot --clean --skip-publish` produces archives that pass a smoke test (`tar tf …` lists expected files; `./agentproxy version` runs from extracted dir).
- Manual smoke test on each platform per Acceptance Criteria above.
- `bats` (or plain shell) test for `scripts/install-online.sh` covering: arch detection, version override, checksum mismatch refusal, user-mode vs system-mode dispatch.
- Uninstall test: install → confirm CA in trust store → uninstall → confirm CA absent.
